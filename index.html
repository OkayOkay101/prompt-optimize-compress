บทเรียนจากการทดสอบจริง

ทำ prompt ให้แม่นขึ้น แล้วค่อยทำให้สั้นลง

สรุปจากการทดสอบ prompt "คณะที่ปรึกษาเชิงกลยุทธ์" กับ Gemini 4 รอบ ว่าอะไรทำให้คำตอบผิด กฎแบบไหนแก้ได้ และย่อ prompt อย่างไรให้ความสามารถไม่หาย

Prompt เดิม→Optimize ให้แม่น→Compress ให้สั้น→ทดสอบเทียบ

Optimize กับ Compress ต่างกันอย่างไร

สองงานนี้มีเป้าหมายต่างกัน ถ้าทำพร้อมกันมักได้ prompt ที่สั้นลงแต่ผิดมากขึ้น จึงควรแยกทำทีละขั้น

Optimize

ทำให้ตอบถูกและซื่อตรงขึ้น

  • ความถูกต้องมาก่อน ยาวขึ้นได้ถ้าจำเป็น
  • เริ่มจากข้อผิดที่เจอในผลจริง
  • แปลงข้อผิดแต่ละจุดเป็นกฎ 1 บรรทัด
Compress

ทำให้สั้นลงโดยไม่เสียความสามารถ

  • ไม่เพิ่มกฎใหม่
  • ต้องทำรายการความสามารถก่อนตัด
  • ทุกความสามารถต้องชี้ได้ว่าอยู่ตรงไหนในฉบับย่อ

ผลทดสอบกับ Gemini 4 รอบ

รอบสิ่งที่ปรับดีขึ้นยังผิด
1ฉบับผสมแรก—อ้างลิงก์ผิดบริบท ตัวเลขในหัวข้อ (1,200) ไม่ตรงสูตร (850) เกณฑ์ไม่ตรงกันแต่ละส่วน
2v2 ใส่เลขกฎและ SELF-CHECKตัวเลขและเกณฑ์ตรงกันแล้วลิงก์ TikTok สิงคโปร์ใช้กับแผน YouTube วันที่ผิด ใช้คำเด็ดขาด
3เพิ่มกฎลิงก์และเกณฑ์ลิงก์ถูกครบ 4 หน้า เงื่อนไขหยุดแผนใช้ "หรือ"ใช้บล็อกเก่าปี 2024 แทนหน้า help และไม่ประมาณรายได้
4เพิ่มกฎรายได้และแหล่งปัจจุบันโครงสร้างดีที่สุดบอกว่าหน้าเว็บ "ไม่ระบุวันที่" ทั้งที่มี และเอายอดวิวสะสมไปเทียบกับต้นทุนรายเดือน

ข้อสังเกตหลัก: ข้อผิดเรื่องวันที่และลิงก์ผิดหน้ากลับมาซ้ำ เพราะโมเดลน่าจะไม่ได้เปิดหน้าเว็บจริง แต่จำ URL มาจากความรู้เดิม prompt อย่างเดียวแก้ได้ไม่หมด ทางที่ได้ผลคือบังคับให้เขียน "(ยังไม่ได้เปิดยืนยัน)" แล้วให้คนตรวจลิงก์ซ้ำ

Optimize

ทำให้ prompt แม่นขึ้น

  1. ทำรายการความสามารถไล่ว่า prompt สั่งอะไรบ้าง เช่น บทบาท รูปแบบผลลัพธ์ กฎ โหมด และตัวอย่าง รายการนี้ห้ามหาย
  2. เก็บข้อผิดจากผลจริงเปิดลิงก์ที่ AI อ้างทุกลิงก์ ตรวจสูตรตัวเลข และดูว่าเกณฑ์ตรงกันทุกส่วนไหม
  3. แปลงข้อผิดเป็นกฎ 1 บรรทัดหนึ่งข้อผิดได้หนึ่งกฎ ใส่เลขกำกับ และอย่าเพิ่มกฎให้ปัญหาที่ยังไม่เคยเจอ
  4. เพิ่มคำถามใน SELF-CHECKให้ AI ตรวจกฎที่มักผิดก่อนส่งคำตอบ โดยไม่ต้องพิมพ์ส่วนตรวจนี้ออกมา
  5. ทดสอบซ้ำ แล้วจดผลคู่กับเวอร์ชันรอบหน้าจะได้รู้ว่ากฎแต่ละข้อเพิ่มเข้ามาเพราะอะไร

กฎพื้นฐานที่ได้จากการทดสอบ

ปัญหาที่เจอกฎที่ใช้แก้
ลิงก์มีอยู่จริง แต่หน้านั้นไม่ได้พูดเรื่องที่อ้างอ้าง URL ได้เมื่อหน้านั้นมีข้อความนั้นจริง ตรงแพลตฟอร์มและประเทศ
อ้างวันที่ทั้งที่ไม่ได้เปิดหน้าหน้าที่ไม่ได้เปิดต้องเขียน "(ยังไม่ได้เปิดยืนยัน)" และห้ามพูดถึงวันที่
ใช้บล็อกประกาศเก่าแทนหน้าคู่มือปัจจุบันใช้หน้า help ฉบับปัจจุบันก่อนบล็อกประกาศ
ตัวเลขในหัวข้อไม่ตรงกับสูตรติดป้าย "(ประมาณการ)" แสดงสูตร และตัวเลขต้องเท่ากับผลของสูตร
ยอดสะสมปนกับยอดรายเดือนหนึ่งเกณฑ์ใช้หน่วยและช่วงเวลาเดียว ต้นทุนรายเดือนก็ต้องคิดจุดคุ้มทุนเป็นรายเดือน
เรียกเกณฑ์ที่ตั้งเองว่า "มาตรฐาน"เรียกว่า "เกณฑ์ที่บอร์ดตั้ง" พร้อมเหตุผล 1 บรรทัด
ใช้คำเด็ดขาดเกินหลักฐานคำว่า "ถาวร" "ทันที" หรือ "ที่สุด" ต้องมีแหล่งรองรับ ถ้าไม่มีให้เปลี่ยนเป็นคำที่ไม่เด็ดขาด

ตัวอย่างจุดคุ้มทุนที่ถูก: ต้นทุนต่อเดือน ÷ RPM × 1,000 = วิวต่อเดือนที่ต้องได้ เช่น ที่ RPM $0.05 ได้ 571,429 วิวต่อเดือน ไม่ใช่ 500,000 วิวสะสม

Compress

ย่อ prompt โดยความสามารถไม่หาย

ย่อ prompt คือการย้ายความหมายไปไว้ในรูปที่สั้นกว่า ไม่ใช่การตัดคำทิ้ง ในการทดสอบ ฉบับที่ย่อหนักสุดแบบรหัสย่อทำให้ข้อความเทมเพลตหลุดออกมาในคำตอบ และอ้างลิงก์ผิด 2 จาก 5

  1. ตัดข้อความที่ซ้ำกันตรงตัว
  2. รวมกฎที่พูดเรื่องเดียวกัน
  3. ใส่เลขกฎ แล้วอ้างเลขแทนการเขียนซ้ำ
  4. ย่อคำอธิบายยาวเป็นกฎ 1 บรรทัด
  5. เขียนคำสั่งเป็นภาษาอังกฤษ แต่หัวข้อผลลัพธ์เป็นไทยเต็ม
เทคนิคผลเหตุผล
ใส่เลขกฎและอ้างเลขใช้ได้ตัดข้อความซ้ำได้มาก และโมเดลอ้างกฎได้ตรงตัว
บอกว่าข้อความใน [ ] เป็นคำสั่ง ห้ามคัดลอกลงคำตอบใช้ได้กันข้อความเทมเพลตหลุดออกมาในคำตอบ
ย่อหัวข้อเป็นคำย่อหรือสัญลักษณ์ระวังผู้ใช้อ่านยาก ผู้ใช้ชอบหัวข้อไทยเต็มมากกว่า
เขียนกฎกว้างเกินขอบเขตเดิมระวังเช่น "ทุกตัวเลขต้องมีแหล่ง" ทำให้ป้าย "ไม่พบแหล่ง" ขึ้นเต็มคำตอบ
แปลงทั้ง prompt เป็นรหัสย่อหรือ DSLห้ามข้อความเทมเพลตหลุดออกมา และอ้างลิงก์ผิด
ตัดตัวอย่างและเงื่อนไขขอบเขตห้ามโมเดลใช้คำเด็ดขาดเกินกว่าที่แหล่งพูดไว้

เช็กลิสต์ก่อนใช้ prompt ฉบับใหม่

  • ทุกข้อในรายการความสามารถยังอยู่ครบ
  • หัวข้อผลลัพธ์เหมือนเดิมทุกตัวอักษร
  • รันชุดทดสอบทั้งฉบับเดิมและฉบับใหม่ แล้วเทียบผลแล้ว
  • เปิดลิงก์ที่โมเดลอ้างทุกลิงก์ และหน้านั้นพูดเรื่องที่อ้างจริง
  • ตัวเลขทุกตัวตรงกับสูตร และเกณฑ์ตรงกันทุกส่วน
  • จดชื่อเวอร์ชันและผลทดสอบไว้คู่กัน
