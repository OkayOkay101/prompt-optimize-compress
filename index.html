เป้าหมายที่ 1

🎯 Optimize: มุ่งเน้น "ความถูกต้องและซื่อตรง"

ทำให้ AI ตอบตรงความจริง ไม่แต่งเติม และตรวจความผิดพลาดได้ด้วยตัวเอง

  • ✓ ความถูกต้องมาก่อนความสั้น: Prompt ยาวขึ้นได้ถ้าจำเป็นต้องเพิ่มกติกาความปลอดภัย
  • ✓ ขับเคลื่อนจากข้อผิดพลาดจริง (Failure-driven): จดทุกจุดที่ AI ตอบผิด แล้วแปลงเป็นกฎ 1 บรรทัด
  • ✓ ไม่เดาปัญหาล่วงหน้า: อย่าเพิ่มกฎดักปัญหาที่โมเดลยังไม่เคยทำผิด
  • ✓ เพิ่ม SELF-CHECK: บังคับให้โมเดลทบทวนตัวเองแบบเงียบๆ ก่อนส่งคำตอบ
เป้าหมายที่ 2

⚡ Compress: มุ่งเน้น "ความกระชับโดยไม่เสียพลัง"

ลดจำนวนคำและโทเคน แต่รักษาผลลัพธ์และพฤติกรรมเดิมไว้ครบ 100%

  • ✓ ห้ามเพิ่มกฎใหม่: หน้าที่เพิ่มกฎเป็นของ Optimizer ส่วน Compressor มุ่งย้ายรูปแบบ
  • ✓ ทำสัญญาความสามารถ (Contract): จดรายการคำสั่งเดิมทั้งหมดไว้ตรวจสอบ ห้ามหล่นหาย
  • ✓ ย่นย่ออย่างเป็นระบบ: ยุบส่วนซ้ำ ซ้อนลำดับข้อความ อ้างอิงด้วยรหัสตัวเลข
  • ✓ ห้ามใช้รหัสย่อลึกลับ (Cryptic DSL): รหัสที่แปลกเกินไปจะทำให้โมเดลตีความเพี้ยน

วิธีแก้ที่ได้ผลจริง: สั่งใน Prompt ชัดเจนว่า หากไม่ได้เปิดอ่านหน้าเว็บจริง ให้ระบุต่อท้ายว่า (ยังไม่ได้เปิดยืนยัน) และห้ามอ้างวันที่เด็ดขาด โดยต้องมีมนุษย์ช่วยตรวจทานลิงก์ซ้ำเสมอ

คู่มือเจาะลึก 1

เสาหลัก Optimize: ทำให้ Prompt ตอบถูกต้องและซื่อตรง

กระบวนการ 5 ขั้นตอนในการยกระดับคุณภาพ Prompt พร้อมกฎพื้นฐาน 7 ข้อที่สกัดจากข้อผิดพลาดจริง

1
แจกแจงรายการความสามารถเดิม (Inventory)
ไล่เรียงคำสั่งทั้งหมด: บทบาท (Role), รูปแบบผลลัพธ์ (Format), กฎข้อบังคับ, โหมดการทำงาน และตัวอย่าง รายการนี้ถือเป็นสัญญาที่จะต้องอยู่ครบ
2
บันทึกข้อผิดพลาดจากผลลัพธ์จริง (Failure-driven)
เปิดดูผลลัพธ์ที่ AI สร้างขึ้นจริง คลิกลิงก์ทุกลิงก์ ตรวจสอบการคำนวณตัวเลข และจับตาจุดที่โมเดลตอบกำกวมหรือแต่งเรื่องขึ้นมาเอง
3
แปลงหนึ่งข้อผิดพลาด เป็นหนึ่งกฎสั้น 1 บรรทัด
อย่าเขียนกฎกว้างเกินจริง ให้เขียนกฎเฉพาะเจาะจงที่แก้ข้อผิดพลาดนั้นตรงๆ กำหนดรหัสเลข (เช่น R1, R2) เพื่อความสะดวกในการอ้างอิง
4
สร้างระบบ SELF-CHECK บังคับทบทวนก่อนตอบ
เพิ่มบล็อก SELF-CHECK เงียบๆ ท้าย Prompt เพื่อให้โมเดลตรวจสอบข้อกำหนดสำคัญ เช่น ลิงก์ตรงไหม? ตัวเลขตรงสูตรไหม? ก่อนที่จะแสดงคำตอบออกมา
5
ทดสอบซ้ำและบันทึกผลคู่กับเวอร์ชัน
รันชุดคำสั่งทดสอบเดิม เทียบผลระหว่างเวอร์ชันเก่าและเวอร์ชันใหม่ เพื่อให้มั่นใจว่าการเพิ่มกฎไม่ส่งผลข้างเคียงให้ส่วนอื่นพัง

7 กฎทองความซื่อตรง (The 7 Baseline Honesty Rules)

กฎที่พิสูจน์แล้วว่าช่วยปิดจุดอ่อนโมเดล AI ได้อย่างชะงัด:

✕
ปัญหา: อ้างลิงก์มีอยู่จริง แต่หน้านั้นไม่ได้พูดเรื่องที่อ้าง
✓
กฎแก้: ใส่ URL ได้เฉพาะเมื่อหน้านั้นมีข้อความนั้นอยู่จริง ตรงแพลตฟอร์มและประเทศ
✕
ปัญหา: อ้างวันที่ของเอกสาร ทั้งๆ ที่ไม่ได้เปิดหน้าเว็บจริง
✓
กฎแก้: หน้าที่ไม่ได้เปิด ต้องวงเล็บ (ยังไม่ได้เปิดยืนยัน) และห้ามอ้างวันที่เด็ดขาด
✕
ปัญหา: ดึงบล็อกประกาศเก่ามาใช้อ้างอิง นโยบายเปลี่ยนไปแล้ว
✓
กฎแก้: ให้ใช้อ้างอิงจากหน้า Help / Documentation ปัจจุบันก่อนหน้าบล็อกประกาศเสมอ
✕
ปัญหา: ตัวเลขในสรุปไม่ตรงกับผลรวมของสูตรคำนวณ
✓
กฎแก้: ติดป้าย (ประมาณการ) แสดงสูตรคำนวณชัดเจน และผลลัพธ์ต้องตรงกับสูตร
✕
ปัญหา: ปะปนตัวเลขสะสมกับตัวเลขรายงวด (เช่น รายเดือน)
✓
กฎแก้: กำหนดหน่วยและช่วงเวลาเดียว จุดคุ้มทุนต้องสอดคล้องกับคาบเวลาของต้นทุน
✕
ปัญหา: AI อ้างว่าเกณฑ์ที่ตัวเองคิดขึ้นมาคือ "มาตรฐานอุตสาหกรรม"
✓
กฎแก้: บังคับระบุว่าเป็น เกณฑ์ที่บอร์ดตั้งขึ้นเอง พร้อมระบุเหตุผลสนับสนุน 1 บรรทัด
✕
ปัญหา: ใช้คำชี้ขาดเกินจริง เช่น "ถาวร", "ทันที", "ดีที่สุด"
✓
กฎแก้: หากไม่มีหลักฐานชัดเจน ห้ามใช้คำเด็ดขาด ให้ปรับระดับคำพูดลงเพื่อความรอบคอบ

🧮 เครื่องมือจำลอง: ตรรกะจุดคุ้มทุนที่ถูกต้อง

ตัวอย่างการคำนวณเพื่อป้องกัน AI สับสนระหว่าง "ยอดสะสม" กับ "ยอดรายเดือน"

คู่มือเจาะลึก 2

เสาหลัก Compress: ย่อ Prompt อย่างไรให้ความสามารถอยู่ครบ

การย่อไม่ใช่การลบคำสั่งทิ้ง แต่คือการย้ายความหมายไปไว้ในรูปแบบที่ประหยัดโทเคนและตีความได้แม่นยำกว่าเดิม

1
ตัดข้อความซ้ำซ้อนโดยสมบูรณ์ (Exact Duplicates)
ตรวจหาประโยคหรือข้อกำหนดที่กล่าวซ้ำในหลายๆ ส่วน แล้วเก็บไว้เพียงจุดเดียวที่ชัดเจนที่สุด
2
รวมกฎที่พูดถึงเรื่องเดียวกัน (Merge Related Rules)
ผสานเงื่อนไขย่อยที่กระจายตัวอยู่ เช่น กฎเรื่องความปลอดภัย กฎเรื่องการอ้างอิง รวมเข้าเป็นหมวดหมู่เดียวกัน
3
ใส่หมายเลขกำกับกฎ (R1, R2 …) แล้วใช้วิธีอ้างอิงเลข
แทนที่จะเขียนประโยคเดิมซ้ำในส่วนแสดงผล ให้ใช้คำว่า "ต้องปฏิบัติตามกฎ R3 และ R5" ช่วยประหยัดข้อความได้มหาศาล
4
ย่อคำอธิบายที่ยืดเยื้อให้กลายเป็นกฎ 1 บรรทัด
ตัดความเรียงอธิบายเหตุผลออก เหลือไว้เฉพาะ "คำสั่งเชิงพฤติกรรม" (Actionable Instruction) ที่โมเดลต้องทำ
5
เขียนโครงสร้างคำสั่งเป็นอังกฤษ แต่คงหัวข้อผลลัพธ์เป็นไทยเต็ม
ภาษาอังกฤษใช้โทเคนน้อยกว่าและโมเดลเข้าใจโครงสร้างได้แม่นยำ ส่วนหัวข้อภาษาไทยจะช่วยให้ผู้อ่านปลายทางเข้าใจง่าย

  • ✔ ตั้งรหัสกฎ (R1, R2): อ้างอิงได้ตรงตัว ลดการเขียนซ้ำโดยโมเดลไม่สับสน
  • ✔ กำกับข้อความในวงเล็บ [ ]: ระบุว่าข้อความใน [ ] คือคำสั่ง ห้ามคัดลอกลงในผลลัพธ์
  • ✔ รักษาบล็อก SELF-CHECK: ย่อถ้อยคำให้สั้นลงได้ แต่ห้ามตัดรายการตรวจสอบทิ้ง
ไฟเหลือง · ต้องระวัง

พิจารณาเป็นกรณี

  • ⚠ ย่อหัวข้อผลลัพธ์เป็นอักษรย่อ: ผู้ใช้ทั่วไปมักอ่านไม่เข้าใจ ควรคงชื่อหัวข้อเต็มไว้
  • ⚠ เขียนกฎกว้างเกินขอบเขตเดิม: เช่น สั่งว่า "ทุกตัวเลขต้องมีแหล่งที่มา" จะทำให้ AI แปะป้าย "ไม่พบแหล่ง" เต็มหน้า
ไฟแดง · ห้ามทำเด็ดขาด

  • ✕ ตัดตัวอย่างและเงื่อนไขขอบเขตทิ้ง: ทำให้โมเดลขาดบริบท และมักใช้คำตัดสินเด็ดขาดเกินจริง
